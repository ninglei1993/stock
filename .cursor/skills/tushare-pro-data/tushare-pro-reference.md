- 基础数据：股票列表、交易日历、ST 列表、上市公司信息、历史列表等

## 2) 代码规范（排查重点）

Tushare 文档强调股票参数通常使用 `ts_code`，后缀应符合交易所规范：

- 上交所：`.SH`（例 `600000.SH`）
- 深交所：`.SZ`（例 `000001.SZ`）
- 北交所：`.BJ`
- 港股：`.HK`

若代码后缀不匹配，通常会导致查询为空或无法命中。

## 2.1 板块与指数代码说明（实践约定）

- 股票多用 `ts_code`（如 `600000.SH`）
- 概念/板块在专题接口中常见 `*.TI` 风格代码（如 `886033.TI`）
- 如果策略按“板块”研究，不要直接用股票接口替代板块接口，需先拉板块成分

## 3) 与扫盘相关的高频接口类别

当任务是“主线/板块/量化扫盘”，优先关注：

- 同花顺行业概念板块
- 同花顺概念和行业指数行情
- 同花顺行业概念成分
- 板块资金流向（THS / DC）
- 涨跌停和炸板数据
- 龙虎榜每日统计单、龙虎榜机构交易单

## 3.1 策略 -> 数据包 -> 接口名（简易决策表）

## 4) 空数据排查清单

1. 是否启用了过窄板块池（仅 1 个板块）
2. 是否同时使用了关键词过滤 + 板块数量上限（导致样本过少）
3. 查询日期是否为有效交易日
4. 板块代码、股票代码后缀是否符合规范
5. 当前账号积分/权限是否覆盖目标接口
6. 是否命中了停用接口或历史接口
7. 是否把“板块策略”误用成“股票接口直取”（缺少板块成分步骤）
8. 是否只扫极小样本（勾选 1 个板块 + 关键词过滤 + 数量上限）

## 5) 使用建议

- 先用“板块成分 + 当日行情”验证数据链路，再引入评分逻辑。
- 出现“评分有值但成分为空”时，优先回查成分拉取与行情聚合步骤。
- 涉及跨源（JQData/Tushare）切换时，记录每次扫盘的数据源标签，避免混淆结论。
- 研究策略时先定义“最小数据包”，再选接口；不要先写因子再补数据。
