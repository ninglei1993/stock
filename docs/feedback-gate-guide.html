1. 概述 Overview

中文：这是 Cursor 项目级 Agent 规则（alwaysApply: true），约束 AI 在每次完成任务后必须通过 MCP 弹窗收集你的反馈，直到你发送明确的完成信号（如 TASK_COMPLETE、Done）。

English: A project-level Cursor rule that forces the Agent to open an MCP feedback popup after each task slice and loop until you send an explicit completion signal.

中文：与全局规则 ~/.cursor/rules/FeedbackGate.mdc 内容一致；复制到本仓库是为了在全局规则未加载时仍能生效。

English: Mirrors the global rule; the repo copy ensures the protocol applies even if the global rule fails to load.

中文：不参与扫盘、回测、Tushare 等业务逻辑。

English: Does not affect application runtime (scan, backtest, data pipelines).

3. [WAITING] 重试 Retry on WAITING

工具返回 [WAITING] 时，Agent 必须立即用相同参数再次调用，直到出现 User Response:。

On [WAITING], the Agent must immediately re-call with the same message/title/context until User Response: appears.

4. 子代理边界 Subagent boundary

通过 Task 启动的子代理不得调用 feedback_gate_chat（会卡住）；必须由主对话在最后统一弹窗。

Subagents launched via Task must NOT call feedback_gate_chat; only the main Agent opens the popup.

  Gate --> User[User popup]
  Task -.->|DO NOT| X[feedback_gate_chat hangs]

8. 不完善之处 Known gaps

  • 无硬 enforcement — 仅靠模型自觉，易漏调。No hooks/CI; compliance is soft.
  • 全局 + 项目双份规则 — 行为依赖加载顺序，无去重。Duplicate global/project rules.
  • 子代理与主代理分工 — 规则未写清汇总责任。Subagent vs main Agent unclear in rule text.
  • [WAITING] 无超时策略 — 易表现为卡住。No timeout/max-retry policy.
  • 完成信号非结构化 — 难以机器区分 DONE vs CONTINUE。Completion signals are informal text.
  • MCP 单点 — 无备用确认通道。Single point of failure.
  • description 为空 — 规则列表难识别。Empty frontmatter description.
  • 无 README / hooks — 协议未与工程流程绑定。Not documented in repo workflow.
  • 每轮必弹窗 — 小问答摩擦大；无豁免定义。High friction for trivial Q&A.
  • 弹窗与聊天双通道 — 状态可能分裂。Popup vs chat can desync.
